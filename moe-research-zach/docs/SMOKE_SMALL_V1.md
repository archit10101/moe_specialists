# smoke-small-v1: ENGINEERING SMOKE TESTS ONLY

> **This configuration is for engineering checks only.** Results from it test the pipeline, memory and
> throughput. They are **not** evidence for or against any hypothesis. The experiment design is the frozen
> full-size `configs/v2` (`EXPERIMENT_MANIFEST.json`), which this configuration does not modify or supersede.

Generated by `make_smoke_configs.py` into `configs/smoke-small-v1/`, with its own `MANIFEST.json` and
`SMOKE_ONLY.txt`. It is derived from `configs/v2/base.json` (sha256 recorded in `derived_from`). The generator
asserts that only these fields differ from v2:
- `model.{d_model, n_layer, moe_layers, n_head, n_experts, top_k, expert_ffn, shared_ffn, dense_ffn, max_seq_len}`
- `routing.pool_size` (= min(E, 2k))
- `train.token_budget`
- `experiment`, `result_label`, `derived_from`

Everything else is unchanged, including:
- the data, and the semantic and fixed caches;
- the accepted F-v2 random cache;
- w = 16, global gate normalization;
- the optimizer, schedule and precision;
- the aux and z coefficients;
- the evaluation settings.

| Item | smoke-small-v1 | v2 (frozen design) |
|---|---|---|
| d_model / layers / heads | 128 / 6 / 8 | 256 / 9 / 16 |
| Dense / MoE layers | layer 0 dense (FFN 512); layers 1–5 MoE | layer 0 dense (FFN 1368); layers 1–8 MoE |
| Routed experts / top-k / pool m | 16 / 2 / 4 | 64 / 6 / 12 |
| Expert FFN / shared FFN | 64 / 128 | 176 / 352 |
| Context | 1024 | 1024 |
| **Total parameters (exact)** | **15,691,392** | **100,670,208** |
| **Active parameters per token (exact)** | **13,971,072** | **37,952,256** |
| Of which embeddings + LM head (untied, vocab 50,304) | 12,877,824 (82.1% of total) | 25,755,648 |
| Non-embedding total / active | 2,813,568 / 1,093,248 | 74,914,560 / 12,196,608 |

The counts are verified two ways in `tests/test_smoke_config.py`: an independent analytic formula, and
`count_parameters` on the instantiated model. Note that the smoke model is dominated by its embeddings; its MoE
layers are a small fraction of compute.

## CPU checks (done, CUDA hidden)

`tests/test_smoke_config.py` passes 10 tests:
- exact parameter counts for both smoke and v2;
- the v2 configs, design and manifest hash are untouched;
- all A–F conditions pass the matched-field check and have identical model dicts, parameter names, shapes and
  seeded initial weights;
- the routing validator rejects pool sizes other than min(E, 2k);
- on real validation data, for **each** of A–F:
  - every non-pad token has exactly **2 distinct** routed experts in [0, 16), plus the shared expert;
  - every constrained selection lies inside its chunk's 4-expert pool;
  - coverage is 0 for A and > 0.5 for B–F;
  - initial CE ≈ ln(50,304).

## Benchmark and smoke commands (NOT RUN)

These have not been run: no CUDA packages are installed and no GPU work has been launched. Each command must
be launched **one at a time** from the project root after `source ./env.sh`. The launcher re-checks GPU 0
occupancy before every command.

```bash
B=configs/smoke-small-v1/base.json
G="env MOE_GPU_LAUNCH=1 MOE_RESEARCH_APPROVE=gpu scripts/gpu_guarded.sh"

# 1. load / forward / causal / equivalence checks on the smoke model
$G "smoke gpu_checks" gpu_checks.py --base $B --execute

# 2. semantic-loss temperatures and lambda for the SMOKE model at random init (smoke-only values)
$G "smoke calibrate" calibrate.py --base $B --device cuda --execute
#    -> read tau_s, tau_r, lambda from runs/<stamp>_calibrate/summary.json; set LAM, TS, TR

# 3. throughput / peak-memory benchmark, 150 optimizer steps (~1.95M valid tokens) per condition
for C in A B D F; do
  $G "smoke benchmark $C" benchmark.py --base $B --condition $C --steps 150 --device cuda \
     --set train.token_budget=3000000 --execute
done
for C in C E; do
  $G "smoke benchmark $C" benchmark.py --base $B --condition $C --steps 150 --device cuda \
     --set train.token_budget=3000000 --set semantic.lambda=$LAM --set semantic.tau_s=$TS --set semantic.tau_r=$TR --execute
done

# 4. at most one tiny end-to-end smoke run for A and one chunk-routing condition (300k valid tokens, 23 steps)
$G "smoke train A" train.py --base $B --condition A --device cuda --run-name smoke_small_A --execute
$G "smoke train E" train.py --base $B --condition E --device cuda --run-name smoke_small_E \
   --set semantic.lambda=$LAM --set semantic.tau_s=$TS --set semantic.tau_r=$TR --execute

# 5. no-training probe pipeline check on the smoke A checkpoint (uninformative at 300k tokens)
$G "smoke probe" probe.py --checkpoint runs/<stamp>_train_smoke_small_A/model.pt --device cuda --execute
```

Dry-runs of these commands parse and plan correctly:
- the benchmarks plan 150 steps / 1,945,347 valid tokens;
- smoke training plans 23 steps / 302,128 valid tokens;
- C and E correctly refuse to run until λ, τ_s and τ_r are set.

Every run directory, `summary.json` and `run_facts.json` carries `result_label = "ENGINEERING SMOKE TEST ONLY -
small model, not experimental evidence"`.
